# 재정경제부 언론 모니터링

재정경제부(가상) 언론 담당자를 위한 **로컬 전용 단일 사용자** 뉴스 모니터링 도구입니다.
매일 여러 차례 자동으로 네이버 뉴스를 검색해 관련 기사를 모으고, 기사를 소제목별로
자동 분류해 브라우저 화면에서 한눈에 훑어볼 수 있게 해줍니다. 요약·키워드 추출은 규칙
기반(단어 빈도 계산)으로 처리해 API 비용이 들지 않고, 소제목 묶음만 선택적으로 Claude
API(Haiku)를 씁니다 — `.env`에 `ANTHROPIC_API_KEY`를 안 넣으면 자동으로 규칙 기반 분류로
동작해, 이 API 없이도 앱 전체는 정상적으로 돌아갑니다.

## 배경

기관 언론 모니터링 담당자는 보통 하루 몇 차례씩 포털에서 관련 키워드를 직접 검색해,
그중 자기 부처와 관련된 기사만 골라 정리한 뒤 보고용 텍스트로 만드는 작업을 반복합니다.
이 앱은 이 과정 중 "검색 → 수집 → 분류 → 정리 → 내보내기"를 자동화하고, 사람은 마지막에
결과를 훑어보며 필요 없는 기사를 걸러내거나(숨기기) 순서를 다듬는 "큐레이션"만 하면
되도록 만들어졌습니다.

## 핵심 기능

### 자동 수집
- 설정한 시각(기본값 09:00 / 10:30 / 13:30 / 16:30)에 자동으로 네이버 뉴스 검색 API를
  호출해 등록된 키워드 그룹으로 기사를 수집합니다. 시각과 하루 실행 횟수는 설정 화면에서
  최소 1개~최대 10개까지 자유롭게 편집할 수 있습니다(코드 수정 불필요).
- **스크랩 시간대 그룹**: 시간대 세트 자체를 여러 개(예: 주중용/주말용, 최대 5개) 만들어둘
  수 있습니다. 그룹마다 독립적인 "사용" 켜기/끄기와 요일(월~일) 선택이 있어 — 그룹을 딱
  1개만 켜두면(수동 오버라이드) 요일과 무관하게 그 그룹이 적용되고, 2개 이상 켜두면
  오늘 요일이 포함된 그룹이 자동으로 적용됩니다(설정 화면에 "오늘 적용 중" 배지로 표시).
  예: 평소엔 "주중"/"주말" 두 그룹을 요일별로 자동 전환하다가, 추석처럼 평일에 쉬는
  날엔 별도 그룹을 새로 만들어 그것만 켜두면 요일 설정과 무관하게 그 그룹이 우선 적용됩니다.
- 앱이 꺼져 있어 놓친 회차가 있으면, 다음에 앱을 켰을 때 **그날 놓친 회차를 전부**
  오래된 것부터 차례로 보충 실행합니다. 회차 하나가 실패해도 나머지는 계속 진행되고,
  여러 회차를 한꺼번에 채워도 자동 발송은 마지막 회차에 대해서만 일어납니다(몇 시간 지난
  회차가 뒤늦게 발송되지 않습니다). 어제 이전 회차는 채우지 못합니다 — 네이버 검색이
  키워드당 최신 1000건까지만 주기 때문에 소급 한계가 하루입니다.
- 앱을 켜는 걸 잊어 회차가 통째로 비는 일을 막으려면 로그인 시 자동 실행을 걸 수 있습니다
  (`bash autostart/install.sh`, macOS 전용 — 자세한 내용과 잠자기 관련 주의사항은
  [autostart/README.md](autostart/README.md) 참고).
- **키워드 그룹**: 검색 키워드를 그룹 단위(최대 8그룹, 그룹당 최대 10개 키워드)로 관리합니다.
  그룹 간에는 항상 OR(어느 그룹이든 조건을 만족하면 수집), 그룹 안에서는 OR/AND를 그룹별로
  고를 수 있습니다. 그룹마다 "정기 스크랩에도 포함" 여부를 따로 켤 수 있어, 주제어 그룹은
  실시간 현황에서만 보고 정식 회차에는 직접 고른 기사만 반영하는 것도 가능합니다.
- 게시일이 당일(한국 시간 기준)인 기사만 수집하고, 지난 날짜 기사는 제외합니다.
- 네트워크 오류 등으로 실패하면 5분 간격으로 최대 3회 자동 재시도합니다.

### 실시간 기사 현황 (`live.html`)
- 예정된 회차와 무관하게, 열 때마다 등록된 키워드 그룹 전체(스크랩 포함 여부와 무관)로
  당일 0시부터 지금까지를 실시간으로 재검색해 보여줍니다. 소제목 분류 없이 최신순
  평평한 목록이며, 언론사·게시 후 경과 시간이 함께 표시됩니다.
- 증분 캐시로 새로고침할 때마다 처음부터 다시 검색하지 않고 "마지막으로 본 시각 이후"만
  추가로 검색합니다(체감 속도 51초→0.9초로 개선). 캐시가 없는 최초 진입(하루 중 처음
  열 때, 키워드 구성을 바꾼 직후)만은 등록된 키워드 전체를 새로 검색해야 하는데, 이때도
  키워드를 하나씩 순서대로 검색하지 않고 최대 5개까지 동시에 검색해 대기 시간을 줄였습니다
  (실측 약 19초→약 5초).
- 기사마다 "📌 담아두기"(다음 정식 회차/초안에 반영할 후보로 임시 보관)와 🗑️ 숨기기가
  가능하고, 지금 진행 중인 회차가 자동으로 골랐을 법한 기사는 "🤖 자동 선별"로 표시해
  일부러 손대지 않아도 되는 기사를 구분해줍니다.

### 스크랩 초안 (`preview.html`)
- 다음 정식 회차가 실행되기 전, 지금까지 수집된 것을 미리 보여주는 화면입니다. 정식
  회차와 동일한 파이프라인(언론사 화이트리스트·중복 제거·소제목 분류)을 그대로 거치므로
  "지금 회차가 끝난다면 어떤 모습일지" 미리 확인하고 다듬을 수 있습니다.
- 여기서 숨기거나 소제목을 옮기면 정식 회차에도 그대로 반영됩니다.
- 증분 캐시(라이브 화면과 같은 방식)와, 이동 조작 시 페이지 전체를 다시 불러오지 않고
  변경된 부분만 갈아끼우는 최적화가 적용돼 있어 반복 조작이 빠릅니다.

### 전송 유예 (담당자 검토 후 발송)
회차가 수집돼도 텔레그램·이메일이 곧바로 나가지 않습니다 — 담당자가 검토를 못 마친 채로
자동 전송되는 걸 막기 위한 안전장치입니다.

- 회차가 수집되면 곧바로 확정본 화면에 반영됩니다(별도의 "확정" 단계는 없습니다).
  확정본 화면 오른쪽 아래 진한 그린 원형 **(발송)** 버튼을 눌러야 텔레그램·이메일(설정에서
  켜둔 채널만)로 실제로 나갑니다 — 예전의 개별 "Telegram"/"Email" 버튼은 이 버튼 하나로
  통합됐습니다.
- 담당자가 5분(기본값) 안에 (발송)을 누르지 않으면 시스템이 스스로 발송합니다 — 결국
  아무도 안 건드리면 예전처럼 완전 자동으로 돌아갑니다. 아직 발송 전이면 "⏱️ MM:SS 후
  자동 발송" 카운트다운이 빨간 글자로 뜨고, 0에 도달하면(탭이 열려있는 경우) 우선 파란
  글자로 "자동발송 완료되었습니다."가 뜬 뒤 화면을 다시 열면 실제 발송 결과로 바뀝니다.
- 발송이 담당자가 아니라 시스템에 의해 자동으로 이뤄졌다면, 그 자리에 회색
  "🤖 HH시 MM분에 자동 발송 완료" 문구가 대신 나타나 누가/무엇이 보냈는지 구분할 수
  있습니다(담당자가 직접 눌러 보냈으면 이 자리는 비어 있습니다).
- 이미 한 번 이상 보낸 회차를 다시 보내면(확정본에서 손본 뒤 재발송) 제목 앞에
  "(수정)"이 자동으로 붙습니다.

- (참고) 처음엔 "수집 → 확정 대기 → (확정) → (전송)" 2단계였고, 회차 종료 30분 전부터
  "지금 마감하기" 버튼도 있었습니다. 확정해도 확정본에서 계속 수정 가능해 애초에 지킬
  필요가 없는 단계였고, 확정 대기 중엔 초안이 "다음 회차 미리보기"가 아니라 "확정 대기
  화면"을 보여줘 혼란스럽다는 실사용 피드백으로 확정 단계 자체를 없앴습니다. 미리
  마감하는 기능도 온라인 기사 특성상(닫은 뒤 들어오는 기사가 유실되거나 다음 회차와
  중복 표시) 함께 없앴습니다.

### 텔레그램 전송
- `.env`에 `TELEGRAM_BOT_TOKEN`을 설정하면(선택 사항 — 없어도 앱은 정상 실행됩니다) 위
  (전송) 버튼으로 텔레그램 발송이 가능해집니다.
- 챗 아이디는 이메일 받는 사람처럼 **여러 명** 등록할 수 있습니다 — 설정 화면
  (`http://127.0.0.1:8765/telegram`)에서 이름·챗 아이디를 등록하고, 사람마다 켜고 끄기
  토글로 지우지 않고도 잠깐 전송 대상에서 뺄 수 있습니다. 챗 아이디를 처음 확인하는
  방법(봇과 대화 시작 → `getUpdates` 호출)도 설정 화면에 안내돼 있습니다.
- 봇 토큰이 없거나 켜진 받는 사람이 없거나 전송에 실패해도 앱 실행이나 스크랩 자체는
  멈추지 않고, 로그에만 경고가 남습니다.

### 이메일 전송
- `.env`에 `EMAIL_SMTP_HOST`/`EMAIL_SMTP_PORT`/`EMAIL_SENDER_ADDRESS`/`EMAIL_SENDER_PASSWORD`를
  설정하면(선택 사항 — 없어도 앱은 정상 실행됩니다) 위 (전송) 버튼으로 이메일 발송이
  가능해집니다. 구글·네이버 등 SMTP를 지원하는 메일이면 어디든 쓸 수 있고, 비밀번호는
  평소 로그인 비밀번호가 아니라 각 메일 서비스에서 발급하는 "앱 비밀번호"를 씁니다.
- **여러 명에게 동시에** 보낼 수 있습니다 — 설정 화면(`http://127.0.0.1:8765/email`)에서
  이름·이메일 주소를 등록하고, 사람마다 켜고 끄기 토글이 있어 지우지 않고도 잠깐 전송
  대상에서 뺄 수 있습니다(예: 휴가 기간에만 다른 사람 켜두기).
- 메일 제목은 헤더 문구("언론 모니터링 [시각] 기준")를 그대로 쓰고, 본문은 기사 URL이
  실제 클릭 가능한 링크가 되도록 HTML로 보냅니다.
- 미설정이거나 받는 사람이 없거나 전송에 실패해도 앱 실행이나 스크랩 자체는 멈추지
  않고, 로그에만 경고가 남습니다. 받는 사람이 여럿일 때 일부만 실패해도 나머지에게는
  계속 보냅니다.

### 자동 소제목 분류 (Claude API, 실패 시 규칙 기반으로 자동 폴백)
- 기사 요약(네이버 API의 description)을 바탕으로, 매 회차마다 소제목을 최대 8개까지
  새로 생성합니다. 제목이 아니라 요약을 기준으로 삼는 이유는, 언론사마다 제목 표현이
  제각각이라 제목만으로는 같은 사건을 다룬 기사끼리도 겹치는 단어가 잘 안 잡히기
  때문입니다 — 보도자료를 비슷한 문장으로 옮겨 쓰는 요약문에서는 공통 단어가 더 잘
  드러납니다. 같은 정책이라도 쟁점이 다르면(예: "정부·여당 입장" vs "야당·시민 비판")
  별도 소제목으로 나누고, 기사가 10건 미만인 작은 회차는 억지로 쪼개지 않습니다.
- 소제목 묶음 자체는 Claude API(기본 Haiku)가 만듭니다 — "등을"·"방안"처럼 뜻이 옅은
  단어가 그대로 소제목이 되던 예전 규칙 기반 분류의 한계를 개선하기 위해서입니다.
  `.env`에 `ANTHROPIC_API_KEY`가 없거나 호출이 실패하면(그리고 대신 쓸 이전 분류도
  없으면) 예외 없이 조용히 기존 규칙 기반(단어 빈도) 분류로 되돌아갑니다 — 이 기능이
  꺼져 있어도 앱은 정상 동작합니다. 요약·키워드 추출은 여전히 규칙 기반입니다. 분류
  결과는 디스크에도 저장돼 앱을 껐다 켜도 이미 붙인 좋은 이름이 유지됩니다.
- **확정본은 재분류하지 않습니다.** 회차가 저장될 때 확정된 소제목 구성을 그대로
  읽어 보여주므로(화면·복사/전송 텍스트가 항상 일치), 화면을 열 때마다 API를 다시
  부르지 않습니다. 담당자가 기사를 숨기거나 옮기거나 이름을 바꿔도 이 저장값이
  그때그때 갱신됩니다. 지금 나온 이름·묶음 자체가 마음에 안 들 때만 **"🤖 전체 기사
  재분류"** 버튼으로 처음부터 다시 만들 수 있습니다 — 소제목 이름·구성·순서가 전부
  새로 만들어지는 되돌릴 수 없는 동작이라, 누르면 항상 확인창이 뜨고(직접 옮겨둔
  기사가 있으면 몇 건인지도 알려줍니다), 숨긴 기사·담아둔 기사는 그대로 유지됩니다.
- **스크랩 초안은 두 버튼으로 나뉩니다.** 그 회차에서 처음 열릴 때(기사 5건 이상일
  때) 딱 한 번만 자동으로 분류하고, 그 뒤로는 새로고침·기사 숨기기·이동/이름변경/
  순서변경을 아무리 해도 다시 부르지 않습니다(재분류가 담당자의 수동 정리 기록을
  통째로 무효화할 수 있기 때문). 그 사이 새로 들어온 기사는 화면 맨 아래
  **"📂 소제목 미분류"** 임시 칸에 모입니다(복사/전송 텍스트에는 이 칸 대신
  "기타"로 나갑니다). 이 칸을 정리하는 방법이 둘입니다 — **"🤖 미분류 배정"**은
  미분류 기사만 골라 기존 소제목에 편입시키는 안전한 동작이라 확인창 없이 바로
  실행되고(기존 소제목의 이름·구성은 건드리지 않음), **"↻ 전체 기사 재분류"**는
  확정본과 같은 파괴적 동작(처음부터 다시 분류)이라 같은 확인창을 거칩니다.
- 소제목 옆 작은 **🤖 배지**는 그 소제목을 AI가 만들었다는 표시입니다. 담당자가
  ✏️로 이름을 바꾸거나 직접 만든 소제목에는 붙지 않고, API 키가 없어 규칙 기반으로
  동작한 회차에도 붙지 않습니다. 화면에만 보이는 표식이라 복사·다운로드·텔레그램·이메일
  발송 텍스트에는 절대 포함되지 않습니다.
- 담당자가 완전히 확인할 것을 전제로 하므로 완벽한 분류일 필요는 없습니다.
- (참고) AI 분류가 시도됐다가 실패했고 대신 쓸 이전 분류도 없어 결국 규칙 기반으로
  떨어진 회차는, 확정본의 자동발송 카운트다운 대신 "⚠️ AI 분류 실패 — 확인 후 직접
  발송해주세요"가 뜨고 자동발송이 보류됩니다 — 화면 전용 경고이며, 담당자가 (발송)을
  직접 눌러야 나갑니다.
- 소제목별 대표 요약(3문장·250자 이내)을 화면 맨 아래에 보여줍니다. [삭제: 2026-09-10]
  그 위에 함께 있던 "🤖 AI가 추출한 주요 키워드"(규칙 기반 단어 빈도 5개)는 없앴습니다 —
  집계 대상이 이미 등록한 검색어로 걸러진 기사라, 빈도를 세도 검색어 주변 단어만
  되돌려줬습니다(HISTORY.md 참고).

### ↩ 되돌리기 (Undo)

- 화면 **왼쪽 아래 ↩ 버튼**으로 방금 한 작업을 한 단계씩 되돌립니다 — 기사 숨기기,
  소제목 이동, 소제목 이름 변경, AI 소제목 재분류가 모두 대상입니다. 되돌릴 작업이
  있을 때만 버튼이 나타나고, 버튼에 마우스를 올리면 "○○ 되돌리기"로 무엇이
  되돌아갈지 알려줍니다.
- 여러 기사를 한꺼번에 숨긴 경우(일괄 숨기기, 소제목 통째로 숨기기)는 한 덩어리로
  묶여서 ↩ 한 번이면 전부 되돌아갑니다.
- 최대 20단계까지 기억하며, 자정이 지나면 초기화됩니다.

### 언론사 우선순위
- 기본값: 방송사(KBS, MBC, SBS, YTN, MBN, JTBC, TV조선) → 주요 언론사(조선일보, 중앙일보,
  한국경제 등) → 그 외 순.
- 설정 화면에서 원하는 언론사만 체크박스로 골라 화이트리스트로 지정하고, "↑"/"↓"·"맨 위"/
  "맨 아래" 버튼으로 순서를 직접 정할 수도 있습니다. 아무것도 안 고르면 기본 우선순위를
  그대로 씁니다.
- **매일경제 표식**: mk.co.kr 도메인은 매일경제(일간지)와 매경이코노미(주간지)가 함께 쓰고
  있어 도메인만으로는 구분이 안 됩니다. 화면에 표시되는 "매일경제"는 빨간 글자로 강조해,
  실제로는 매경이코노미일 수 있다는 걸 알려줍니다(화면 전용 표식 — 화이트리스트 비교·
  정렬·복사/내보내기에는 영향 없음).

### 사진기사·인사 발령 기사 제외 (선택)
- **기본은 모두 수집됩니다.** 설정 화면(`http://127.0.0.1:8765/scrap-page`)에서
  "자동선별 시 [인사] 기사 제외하기" / "자동선별 시 [포토] 기사 제외하기"를 각각 켜야
  그 유형의 기사가 정기 회차 수집에서 빠집니다. 켠 경우에도 `[속보]`가 붙은 기사는 다른
  힌트 단어가 같이 있어도 예외로 항상 수집합니다(단신이어도 속보는 놓치지 않기 위함).
- 포토 기사는 제목의 힌트 단어(포토, [포토], 사진, 화보, 포토뉴스, PHOTO — 대소문자 무시)
  로 우선 판별하고, 연합뉴스·뉴시스·뉴스1 등 통신사가 이런 표식을 아예 안 붙이는 경우를
  위해 요약문의 사진 캡션 특유 신호(사진기자 이메일, 촬영 날짜 도장 등)와 제목이
  서술어 없이 "~하는 OOO 부총리"처럼 끝나는 패턴을 함께 감지해 추정합니다. 이 추정은
  확신할 수 없으므로 실시간 현황·초안 화면에서는 지우지 않고 "📷 사진 추정" 배지로만
  보여주고, 실제로 걸러내는 건 정기 회차 수집에서 위 옵션을 켰을 때뿐입니다.
- 완전히 동일한 제목의 기사는 언론사 우선순위가 가장 높은 것 1건만 남깁니다(중복 게재는
  허용하되, 진짜 중복은 걸러냄) — 이 규칙은 위 옵션과 무관하게 항상 적용됩니다.

### 기사 큐레이션 (화면에서 직접 조작)
- **🗑️ 숨기기 / 되돌리기**: 보고에서 빼고 싶은 기사를 화면에서 바로 숨길 수 있습니다.
  원본 수집 데이터는 지우지 않고 "숨긴 기사 URL 목록"만 별도로 기록하며, 설정 화면
  "숨긴 기사 관리"에서 언제든 되돌릴 수 있습니다.
- **↑ / ↓ 순서 조정**: 같은 소제목 안에서 순서를 바꿀 수 있고, 소제목 맨 위/아래에서 한
  번 더 누르면 옆 소제목으로 기사를 통째로 옮길 수도 있습니다(소제목 경계 넘나들기).
- **체크박스로 여러 기사 한 번에 옮기기**: 자동 분류가 완벽하지 않아 3~4개씩 바로잡아야
  할 때, 기사마다 있는 체크박스로 여러 개를 골라 화면 하단에 나타나는 바에서 원하는
  소제목으로 한 번에 옮길 수 있습니다. 기사 하나만 바로 옮기고 싶으면 각 기사 옆
  "다른 소제목으로" 드롭다운을 바로 선택해도 됩니다(둘 다 스크랩 초안·확정본 화면
  모두에서 지원).
- **+ 새 소제목 만들기**: 자동 분류로는 절대 나오지 않는 이름의 소제목을 미리 만들어둘
  수 있습니다. 기사가 하나도 없어도 화면에 점선 테두리로 표시되며, 체크박스나 드롭다운으로
  기사를 옮겨 담으면 일반 소제목과 동일하게 동작합니다. 안 쓰게 되면 🗑️로 삭제할 수
  있습니다.
- **✏️ 소제목 이름 바꾸기**: 자동 생성된 소제목 이름이 마음에 안 들면 직접 다른 이름으로
  바꿀 수 있습니다. 분류 로직 자체는 그대로 두고 화면에 보여주는 이름만 바뀝니다. 같은
  화면 안에서 이미 쓰이고 있는 이름과 겹치면 저장을 막습니다(다른 회차·다른 화면끼리
  같은 이름은 허용).
- **소제목 전체 선택 · 일괄 이동/숨기기**: 소제목 헤더의 체크박스로 그 안 기사를 한 번에
  전부 선택할 수 있고, 화면 하단에 나타나는 바에서 선택한 기사들을 통째로 위/아래로
  이동하거나(같은 소제목 안에서만) 한 번에 숨길 수 있습니다.
- **+ 새 소제목 만들기**: 자동 분류로는 나오지 않는 이름의 소제목을 미리 만들어둘 수
  있습니다. 사용자가 만든 소제목은 하늘색 점선 테두리로 항상 표시되어 자동 분류와
  구분됩니다.
- **소제목 순서 조정**: 소제목 헤더의 ↑/↓로 화면에 나열되는 소제목 순서 자체를 바꿀 수
  있습니다(기사 내용과 무관, 표시 순서만).
- **소제목 미니 목차**: 화면 오른쪽 아래 ☰ 버튼을 누르면 지금 화면의 소제목 이름 목록이
  뜹니다. 이름을 누르면 그 소제목 위치로 스크롤 이동하고, 각 항목 옆 작은 ▲▼로 그
  자리에서 바로 소제목 순서를 바꿀 수 있습니다(소제목이 많아 스크롤이 길어질 때 유용).
  사용자가 만든 소제목은 이 목차 안에서도 볼드로 표시됩니다.
- **새 소제목의 기본 위치**: "+ 새 소제목 만들기"로 만든 소제목은 화면 맨 위(다른
  사용자 지정 소제목들 바로 다음, 만든 순서 유지)에 나타납니다. 어디까지나 처음
  만들 때의 기본 위치일 뿐이라, 이후 ↑/↓나 미니 목차로 자유롭게 옮길 수 있습니다.
- **보기 순서 전환**: "소제목별 / 소제목 내 시간순 / 시간순 / 언론사순" 중 골라 화면에
  나열되는 순서만 바꿔 볼 수 있습니다(저장된 소제목 구성 자체는 바뀌지 않는 표시 전용
  기능).
- **🔄 원문에서 다시 가져오기 / ✏️ 직접 수정**: 네이버 요약이 사진 설명이나 문장 중간에서
  잘려 있을 때, 기사 카드에 마우스를 올리면 나타나는 🔄로 그 기사만 원문 페이지에서
  제목·요약을 다시 가져올 수 있습니다. 그래도 안 되면 ✏️로 제목·요약을 직접 입력할 수
  있습니다. 둘 다 한 번 고치면 이후 모든 화면(확정본·초안·실시간 현황·지난 기사)에
  똑같이 반영됩니다.
- **이동 표시**: 기사나 소제목을 옮기면 방금 옮긴 항목이 잠깐 연두색으로 표시되어, 여러
  개를 연달아 조정할 때도 방금 뭘 옮겼는지 바로 알 수 있습니다.
- 위 모든 큐레이션은 **최신 회차(스크랩 확정본)에서만** 가능합니다. 다음 회차가 수집되는
  순간 이전 회차는 "지난 기사"로 넘어가며 읽기 전용이 됩니다(🗑️ 숨기기 제외).

  단어를 추가·삭제할 수 있습니다.

  바로 바뀝니다(화면에 이미 표시된 같은 단어도 함께 바뀜).
- 팝오버는 🖍️를 다시 누르거나 화면 바깥을 클릭하면 닫힙니다.

  수 있습니다. 저장하면 복사/`.txt`/전송 텍스트에도 헤더 바로 아래 한 줄로 포함됩니다.
  하나의 값을 초안·확정본이 공유하므로, 초안에서 적어두면 그 회차가 확정본이 될 때

  메모가 이미 있으면 이 버튼은 사라지고(입력칸이 이미 열려 있으니 다시 열 필요가

  있습니다(다시 "저장"으로 바뀜) — 저장된 상태와 편집 중인 상태가 한눈에 구분됩니다.

- 최근 7일간 저장된 회차를 날짜별 → 시간대별 토글로 펼쳐볼 수 있습니다. 7일이 지난
  회차는 자동으로 삭제되어 조회 목록에서도 사라집니다.
- 회차가 저장되는 시점의 소제목 구성을 함께 저장해두므로, 지난 회차를 열어도 그때
  실제로 봤던 소제목별 구성 그대로 복원됩니다(재분류하지 않음). 다만 읽기 전용이라
  순서 조정·소제목 이동은 지난 기사 화면에서는 할 수 없습니다(🗑️ 숨기기만 가능).

### 내보내기 / 새로고침
- 소제목별 결과를 클립보드로 복사하거나 `.txt` 파일로 내보낼 수 있습니다. 버튼·아이콘
  글자는 복사 결과에 포함되지 않습니다.
- 스크랩 확정본은 1분마다 자동으로 새로고침됩니다(`<meta http-equiv="refresh">`). 숨기기/
  이동 등 조작은 클릭 즉시 서버에 저장되므로 새로고침 타이밍과 겹쳐도 편집 내용을
  잃지 않습니다.

## 화면 구성

| 화면 | 파일 | 설명 |
|------|------|------|

항목이 늘면서 이니셜이 서로 겹치는 문제가 있었습니다):

- 검색 키워드(그룹) · 형광펜 긋기
- **뉴스 스크랩**: 수집 시간(스케줄 그룹) · 언론사 선택·순서 지정 · 수집 범위
  (포토/인사 기사 포함 여부 등) · 본문 형식
- **기타**: 워드클라우드 제외어 · 텔레그램 전송 · 이메일 전송

숨긴 기사 관리는 별도 메뉴 없이 각 화면 하단 고정 바의 🗑️ 아이콘으로 바로 이동합니다.

## 아키텍처

서버 프레임워크(FastAPI, Django 등) 없이, 파이썬 스크립트가 결과를 정적 HTML 파일
(`index.html`, `history.html`, `home.html`)로 생성하고 브라우저로 엽니다. `live.html`·
`preview.html`은 저장하지 않고 요청이 올 때마다 그 자리에서 새로 계산해 생성합니다.
데이터는 SQLite 대신 로컬 JSON 파일(`data/`)에 저장합니다.

예외적으로 딱 한 곳, 설정 저장·기사 큐레이션(숨기기/순서 조정/일괄 이동/소제목 만들기/
이름 바꾸기)을 처리하기 위한 최소 로컬 HTTP 서버(`app/settings_server.py`, 표준
라이브러리 `http.server`만 사용, `127.0.0.1`에서만 동작)를 둡니다. 이 서버는 정적 화면
파일도 같은 출처(origin)로 함께 서빙하는데, 이는 최신 브라우저가 보안상 http 페이지에서
file:// 경로로의 이동을 막기 때문에 필요한 우회입니다.

`live.html`·`preview.html`은 열 때마다 네이버 API를 다시 검색하는 대신, 마지막으로
확인한 시각 이후 것만 추가로 검색하는 증분 캐시(`app/live_cache.py`, `app/preview_cache.py`)를
씁니다. `preview.html`의 ↑/↓ 이동은 페이지 전체를 새로고침하지 않고 서버가 돌려주는
변경분(JSON)만 DOM에 반영합니다.

자바스크립트는 "꼭 필요한 곳만" 최소로 사용합니다 — 클립보드 복사, 기사 숨기기/순서
조정/일괄 이동(`fetch`로 로컬 서버에 비동기 저장), 소제목 이름 바꾸기·새 소제목 만들기
(`prompt()` + `fetch`) 정도입니다. 나머지는 순수 HTML/CSS(`<details>`/`<summary>` 토글,
`<meta http-equiv>` 자동 새로고침, `:has()` 선택자 등)로 구현합니다.

자세한 설계는 [DESIGN.md](DESIGN.md), 전체 요구사항은 [PRD.md](PRD.md), 지금 유효한
규칙·구조는 [CLAUDE.md](CLAUDE.md), 왜 그렇게 바뀌어왔는지(변경 이력)는
[HISTORY.md](HISTORY.md), 반복되는 설계·UX 원칙은 [CODING_CONVENTIONS.md](CODING_CONVENTIONS.md),
Claude API 호출 지점·비용은 [LLM_COST_USAGE.md](LLM_COST_USAGE.md)를 참고하세요.

## 설치 및 실행

```bash
git clone https://github.com/sweetgreetings/news-scrap.git
cd news-scrap
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`.env` 파일을 프로젝트 루트에 만들고 네이버 뉴스 검색 API 키를 넣습니다
([네이버 개발자센터](https://developers.naver.com)에서 애플리케이션 등록 후 발급,
"검색" API 사용 설정 필요):

```
NAVER_CLIENT_ID=발급받은_클라이언트_ID
NAVER_CLIENT_SECRET=발급받은_클라이언트_시크릿
```

텔레그램 전송 기능을 쓰려면(선택 사항) 같은 파일에 봇 토큰을 추가합니다.
[@BotFather](https://t.me/BotFather)에게 말을 걸어 새 봇을 만들면 토큰을 받을 수 있습니다:

```
TELEGRAM_BOT_TOKEN=발급받은_봇_토큰
```

받는 사람(챗 아이디)은 `.env`가 아니라 앱 실행 후 설정 화면
(`http://127.0.0.1:8765/telegram`)에서 등록합니다 — 봇과 대화(또는 그룹 초대)한 뒤
`https://api.telegram.org/bot<토큰>/getUpdates`를 호출하면 챗 아이디를 확인할 수
있고, 이 방법이 설정 화면에도 안내돼 있습니다. 여러 명 등록·켜고 끄기 토글이 가능합니다.

이메일 전송 기능을 쓰려면(선택 사항) 같은 파일에 SMTP 정보를 추가합니다. 비밀번호는
평소 로그인 비밀번호가 아니라 메일 서비스에서 2단계 인증을 켠 뒤 발급받는 "앱
비밀번호"입니다(구글: 계정 → 보안 → 앱 비밀번호, 네이버: 네이버ID 관리 → 보안설정 →
앱 비밀번호 — 메일 자체 설정에서도 POP3/IMAP·SMTP 사용을 켜야 합니다):

```
EMAIL_SMTP_HOST=smtp.naver.com
EMAIL_SMTP_PORT=587
EMAIL_SENDER_ADDRESS=보내는사람@naver.com
EMAIL_SENDER_PASSWORD=발급받은_앱_비밀번호
```

소제목 자동 분류에 Claude API를 쓰려면(선택 사항 — 없으면 기존 규칙 기반 분류로
동작합니다) [Anthropic Console](https://console.anthropic.com)에서 발급받은 키를
추가합니다:

```
ANTHROPIC_API_KEY=발급받은_API_키
```

실행:

```bash
python3 main.py
```

브라우저가 자동으로 열리며 진입 화면(`home.html`)을 보여줍니다. 앱을 켜둔 동안 설정한
시각마다 자동으로 수집이 실행됩니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요.

## 설정 방법

앱 실행 중 `http://127.0.0.1:8765/` 로 접속하면 설정 메뉴가 뜹니다. 각 하위 페이지에서
값을 바꾸고 저장하면 별도 코드 수정 없이 바로 다음 회차부터(또는 스크랩 시간처럼 다음
확인 주기 안에) 반영됩니다.

## 데이터 저장

`data/` 폴더 아래에 다음 파일들이 생성됩니다 (모두 git에서 제외됨):

- `articles/YYYY-MM-DD_HH-MM.json`: 회차별 수집 기사 원본(언론사·제목·URL·요약) + 저장
  시점의 소제목 구성(`group` 필드, 지난 기사 화면 복원용) + 확정·전송 상태
  (`confirmed`/`confirmed_at`/`send_count`/`sent_by`/`sent_at` — 확정·전송이 담당자
  직접 조작인지 자동 처리인지까지 기록)
- `settings.json`: 키워드 그룹, 언론사 화이트리스트, 형광펜 단어, 출력 형식, 스케줄 그룹
- `hidden_articles.json`: 숨긴 기사 URL 목록
- `group_overrides.json`: 소제목 경계를 넘어(또는 일괄 이동으로) 수동으로 재배정한 기사 기록
- `group_labels.json`: 소제목에 붙인 사용자 지정 이름표
- `custom_groups.json`: "+ 새 소제목 만들기"로 만든, 자동 분류엔 없는 소제목 이름 목록("📌 담아두기"와 같이 당일까지만 유지, 자정 이후 초기화)
- `manual_articles.json`: 실시간 현황에서 "📌 담아두기"한 기사(당일 유지)
- `draft_pending_articles.json`: 초안에서 "예약"해둔 기사(다음 정식 회차에 합류 후 소멸)
- `preview_order.json`: 스크랩 초안에서 조정한 소제목 내 순서(정식 회차 저장 시 반영 후 소멸)
- `live_cache.json` / `preview_cache.json`: 실시간 현황·초안의 증분 검색 캐시(당일 유지)
- `group_order.json`: 소제목 자체의 화면 표시 순서(이름 목록, 없는 이름은 맨 뒤로 취급)
- `manual_keyword_note.json`: "+ 직접 키워드 작성하기"로 남긴 자유 서식 메모 1개(전역 공유)
- `summary_overrides.json`: 🔄/✏️로 고친 기사 제목·요약(URL별, 필드 단위 부분 저장)
- `email_recipients.json`: 이메일 받는 사람 목록(이름·주소·켜고 끄기 상태)
- `telegram_recipients.json`: 텔레그램 받는 사람 목록(이름·챗 아이디·켜고 끄기 상태, 이메일과 동일한 방식)
- `llm_classification_cache.json`: AI 소제목 분류 결과 캐시(디스크에 저장돼 앱 재시작에도 유지)
- `undo_stack.json`: ↩ 되돌리기용 큐레이션 상태 스냅샷(최대 20단계, 당일 유지)
회차 데이터는 저장된 지 1년(`RETENTION_DAYS`)이 지나면 자동으로 삭제됩니다.

## 알려진 한계

- **인터넷 배포 불가**: 이 앱은 처음부터 "내 컴퓨터에서만 실행"을 전제로 설계됐습니다.
  - 스케줄러가 앱이 켜진 동안 계속 도는 무한 루프 구조라 서버리스(Vercel 등) 환경에서
    실행할 수 없습니다.
  - 기사·설정 데이터를 로컬 파일에 저장하므로, 서버리스 환경에서는 배포마다 초기화됩니다.
  - 설정 저장 서버에 **로그인/인증이 없습니다** — "로컬에서만 접속 가능"을 전제로
    의도적으로 만들지 않았습니다. 이 상태로 인터넷에 노출하면 누구나 로그인 없이
    키워드 변경, 기사 삭제 등이 가능해집니다.
  - 그러므로 이 저장소를 그대로 Vercel 등에 배포하지 마세요. 인터넷 공개가 꼭 필요하면
    별도의 아키텍처 재설계(실제 데이터베이스, 서버리스 스케줄, 인증 추가)가 필요합니다.
- 컴퓨터가 잠자기 상태였던 동안에는 예약된 정시 실행이 되지 않으며, 깨어난 직후 그날
  놓친 회차를 오래된 것부터 전부 보충 실행합니다(어제 이전은 불가).
- 소제목 분류는 완벽한 정확도를 보장하지 않습니다(담당자가 검토·큐레이션하는 것을
  전제로 한 설계입니다).
- 숨기기/순서 조정/일괄 이동/소제목 만들기 등 모든 큐레이션은 **최신 회차(스크랩
  확정본)에서만** 가능합니다. 다음 회차가 수집되면 이전 회차는 "지난 기사"로 넘어가며
  읽기 전용이 됩니다(🗑️ 숨기기만 예외). 지난 회차도 편집 가능하게 하려면 회차별로
  독립적인 편집 상태를 갖도록 저장 방식 자체를 다시 설계해야 합니다(현재 보류).
- 지금은 "혼자 쓰는 로컬 도구"를 전제로 합니다. 같은 사무실 네트워크에서 여러 명이
  함께 보게 하려면 서버 바인딩 주소 변경·최소한의 권한 구분(관리자/뷰어)이 추가로
  필요합니다 — 팀 전체가 각자 계정으로 큐레이션까지 하는 형태는 아직 지원하지 않습니다.
