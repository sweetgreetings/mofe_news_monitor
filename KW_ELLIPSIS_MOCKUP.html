🔍 검색어 말줄임 — 확정본·초안 액션 줄

아래 두 구역은 같은 기사 6건을 같은 카드 폭(800px)·같은 폰트로 그린 것이다. 실제 app/renderer.py의 CSS 값을 그대로 옮겼다 — 카드 폭 800px, 액션 줄 padding-left: 28px, 검색어 0.8rem. 빨간 점선은 밀려난 액션 묶음, 초록 점선은 제자리에 고정된 액션 묶음.

지금 액션 줄이 밀려난다

검색어에 폭 제한이 없어 .article-actions(flex-shrink: 0)를 통째로 다음 줄로 밀어낸다. 스크린샷의 그 상태.

제안 — 폭으로 자른다 액션 줄 고정

max-width + text-overflow: ellipsis. 슬라이더로 폭을 바꿔가며 몇 건이 잘리는지 직접 재보고 값을 정하면 된다. 잘린 행은 마우스를 올리면 전체 검색어가 툴팁으로 뜬다(안 잘린 행은 원래 설명 툴팁 유지).

200px 이 폭에서 0 / 6건 잘림 · 액션 밀림 0건

읽는 법. 폭을 줄이면 잘리는 건수가 늘고, 늘리면 어느 지점부터 다시 액션 줄이 밀리기 시작한다. "액션 밀림 0건"을 유지하는 가장 큰 값"이 상한이고, 그보다 여유를 조금 더 두는 게 안전하다 — 제목 길이·언론사명 길이는 매번 다르지만 액션 묶음 폭은 항상 같으니, 이 상한은 카드 폭이 바뀌지 않는 한 고정이다.
실시간현황의 210px을 그대로 쓰면 안 되는 이유도 여기서 보인다 — 이 화면은 액션 묶음에 「다른 소제목」 드롭다운(100px)이 하나 더 있어 여유가 그만큼 적다.
초안(preview.html)도 같은 값을 쓰면 된다 — 같은 render_article()을 그대로 import하고 컨테이너도 똑같이 800px이라 상한이 동일하다. 값 하나로 두 화면이 다 덮인다.

실제로 들어갈 CSS

/* app/renderer.py — .kw-inline 아래 */
.kw-inline {{ font-size: 0.8rem; color: {muted};
  display: inline-flex; align-items: center; gap: 4px;
  min-width: 0;  /* flex 자식이라 이게 없으면 ellipsis가 안 먹는다 */
}}
.kw-inline .kw-v {{ color: {text_soft};
  display: inline-block; max-width: ???px;
  overflow: hidden; text-overflow: ellipsis; white-space: nowrap;
  vertical-align: -3px;  /* inline-block이 되며 baseline이 틀어지는 보정 */
}}

그리고 실시간현황의 markTruncatedKeywords()와 같은 JS 한 조각 — scrollWidth > clientWidth인 행에만 title을 전체 검색어로 바꾼다. 글자수 추정이 아니라 이 브라우저·이 폰트 기준 실제 잘림 여부다.
