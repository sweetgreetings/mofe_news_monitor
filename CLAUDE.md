## Project status

The app is implemented and working. Entry point: `python3 main.py` (starts the scheduler loop, the local settings/curation server, and opens the browser). Tests: `python3 tests/test_integration.py`. No package manager beyond `requirements.txt` (`requests`, `python-dotenv`) — no linter or type checker is configured.

## What this app is

A single-user, local-only desktop-style web app for a press-monitoring worker at the Ministry of Economy and Finance (재정경제부). It periodically scrapes Naver News search results for configured keywords, groups the articles into auto-generated sub-headings, and shows the results in a browser at `localhost`. Full spec: [PRD.md](PRD.md); condensed version: [prd_lite.md](prd_lite.md).

## Architecture (PRD section 8 original plan superseded — see DESIGN.md §3)

The original PRD plan (FastAPI + SQLite + APScheduler) was replaced during design with a simpler file-based approach to lower implementation difficulty. This is what's actually built:

- **No web framework**: plain Python scripts regenerate static HTML files (`index.html`, `history.html`, `home.html`) that are opened in the browser. No FastAPI, no Django.
- **Storage**: local JSON files under `data/` (`articles/`, `settings.json`, `hidden_articles.json`, `group_overrides.json`, `group_labels.json`) — no SQLite.
- **Scheduling**: a lightweight polling loop (`app/scheduler.py`, no APScheduler), checking every 60s. Each slot is a `{start, end}` time window (default: 00:00–09:00 / 09:00–10:30 / 10:30–13:30 / 13:30–16:30 KST), user-editable from the settings screen (1–10 slots, no code change needed). `end` is the slot's identity (used for the storage filename and header, same as before); `start` is the lower bound for that slot's collection window (see Collection below). Only the single most-recently-missed slot is caught up on next tick if the app was closed during a scheduled time — using its *configured* start, not the actual catch-up time; the loop pauses during OS sleep like any other process and resumes catch-up on wake.
- **One exception to "no server"**: `app/settings_server.py` is a minimal `http.server`-only local HTTP server on `127.0.0.1:8765` that handles settings saves and article curation (hide/reorder/rename), and also serves the three static HTML screens from the same origin (needed because browsers block navigation from `http://` pages to `file://` paths).
- **External API**: Naver News Search API — credentials read from `.env` (`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`), never hardcoded or committed. [Added: 2026-08-03] Telegram Bot API (`app/telegram_bot.py`) is a second, optional external integration — credentials (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) also come from `.env`, but unlike Naver's, missing/invalid Telegram credentials never stop the app from starting or running; sends are just skipped with a log warning (`is_configured()`).
- **Target OS**: Windows, single local user, no auth/login layer.
- No separate LLM/AI API is used for classification — sub-heading grouping, summaries, and keyword extraction are rule-based (word-frequency grouping over article **descriptions**, not titles — title wording varies too much by outlet to group well), explicitly to avoid API costs.

## Core business rules to preserve (PRD section 5)

These are product-defined constraints, not implementation details — get them wrong and the feature is wrong even if the code runs:

- **Collection**: [Updated: 2026-07-25] Keyword *groups*, not a flat keyword list — up to `MAX_KEYWORD_GROUPS` (6) groups, each with up to `MAX_KEYWORDS_PER_GROUP` (7) keywords and its own OR/AND mode, at least 1 group required. Between groups the relationship is always OR (any group's condition being met is enough); within a group it's that group's own OR/AND. The "기관 정보 (기본)" group is no longer fixed/read-only — it's seeded once on first load from `app/config.py` `BASE_GROUP_KEYWORDS` (재정경제부/재경부/기획재정부/기재부/정부/구윤철/이형일) via a one-time migration flag (`app/settings.py` `load_settings`, `base_group_seeded`), then behaves exactly like any other group: renamable, its keywords editable, and the whole group deletable (an admin's institution can change). [Updated: 2026-07-25] Each group also has an `include_in_scrap` flag (checkbox in the settings screen, one-time migration defaults existing groups to `True` for backward compat): the scheduled/official scrape (`app/scraper.py` `collect_run`) only searches groups with this flag on, while the real-time view (`app/live_renderer.py`, see below) always searches *all* groups regardless of the flag. At least one group must have it on (`app/settings.py` `validate_keyword_groups`). This lets an admin keep broad topic groups (e.g. 부동산, 환율) live-view-only and hand-pick individual articles into the official scrape via the "→ 스크랩" button, without those topics silently inflating every scheduled run. Editable from the settings screen (no code change needed) — `app/settings.py` `save_keyword_groups`/`validate_keyword_groups`, `app/naver_api.py` `search_articles_by_groups` (dedups identical keywords across groups so the Naver API isn't called twice for the same word). No result-count cap, only same-day (KST) articles.
- **Real-time view** (`app/live_renderer.py`, route `/live.html`): separate from scheduled collection — regenerates fresh on every request (no caching, no auto-refresh; manual "새로고침" link only) by live-searching *all* keyword groups (ignoring both the outlet whitelist and the `include_in_scrap` flag) for today (KST midnight–now), sorted newest-first by `pub_date`. Shows outlet, title, URL, and a JS-computed "N분 전" per article (recalculated client-side on every load so it never goes stale) — no sub-heading grouping, no highlight, no AI summary. [Updated: 2026-07-26] Two independent checkboxes on `/live-settings` (`app/settings.py` `save_live_settings`, both default off — raw Naver results): `live_dedup_titles` collapses exact-duplicate titles *across all outlets* (not scoped to a single outlet — a same-title-different-link article from the same outlet is intentionally left as-is, since the point of this view is showing what's live at Naver right now), and `live_exclude_photo` applies the same `exclude_photo_articles` filter used by the scheduled scrape (`app/filters.py`). A "→ 스크랩" button on each row (disabled until at least one scheduled run exists today) calls `app/manual_articles.py` `add_manual_article`, which appends the article to a same-day-only list rendered as a "📌 직접 추가한 기사" section at the bottom of `index.html`/`history.html` (own up/down ordering via `move_manual_article`, hide reuses the normal hidden-articles mechanism) — visible on screen but excluded from copy/`.txt` export, and cleared automatically at midnight. [Updated: 2026-07-29] `app/live_renderer.py` `_auto_drafted_urls()` flags, per row, articles the currently-in-progress draft round (`app.scheduler.next_pending_slot`) would likely pick up on its own — approximated locally from data live.html already has (no extra Naver call): `pub_date` inside the round's window, outlet-whitelist match, `include_in_scrap`-flagged groups' keywords found in title/summary, and photo/personnel exclusion respecting the scrap-page toggles. Matching rows show a disabled "🤖 자동 선별" button instead of "📌" (precedence: hidden > scrapped > pinned > auto-drafted > normal) — an approximation, since group AND-mode and title-dedup aren't replicated.
- **Scheduled scrape photo inclusion** [Added: 2026-07-26]: `/scrap-page` settings screen (`app/settings.py` `save_scrap_page_settings`, field `include_photo_in_scrap`, default off) lets an admin opt the *scheduled* run into keeping photo/on-site articles instead of dropping them (`app/scraper.py` `collect_run`) — the title-dedup rule (`deduplicate_by_title`) still always applies regardless of this flag, only the photo-hint-word exclusion is conditional. Off by default (current behavior unchanged); turning it on means photo articles flow all the way through sub-heading classification and AI summary, so the admin is expected to hide them manually via 🗑️ if unwanted.
- **Waiting-for-first-scrap placeholder** [Added: 2026-07-26]: `app/renderer.py` `generate_waiting_page()` writes a "🐰⏱️ 아직 스크랩 시간 전입니다" placeholder to `index.html` whenever `app/storage.py` `is_today()` says the latest saved run isn't from today — both at app startup (`main.py`, replacing the old `_WAITING_PAGE` constant that only handled the zero-runs-ever case) and every scheduler tick while `app/scheduler.py` `current_active_slot()` is `None` (i.e., before today's first slot has completed — this check is time-of-day-only, so it naturally resets to "waiting" every midnight without tracking dates explicitly). Prevents yesterday's last scrap screen from lingering past midnight until today's first scheduled run completes and overwrites it.
- **매일경제/매경이코노미 구분 불가 표식** [Added: 2026-07-29]: mk.co.kr 도메인은 매일경제(일간지)와 매경이코노미(주간지)가 함께 쓰지만 `app/naver_api.py`의 언론사 판별은 도메인 기준이라 둘을 구분할 수 없다. `app/naver_api.py` `outlet_display_label()`이 화면 표시 시 "매일경제"를 "매일경제**"로 표시해 실제로는 매경이코노미일 수 있다는 걸 알려준다 — `app/renderer.py` `render_article`(라인 텍스트), `app/live_renderer.py` `_render_row`(outlet-tag), `app/settings_server.py` `render_hidden_page`(숨긴 기사 라벨) 세 곳에 적용. 화이트리스트 비교·우선순위 정렬·복사/`.txt` 내보내기에 쓰이는 원본 `outlet` 값은 그대로 "매일경제"를 유지한다(화면 전용 표식). [Fixed: 2026-08-03] MBN도 같은 매경미디어그룹이라 mk.co.kr을 공유하는데, MBN 기사의 실제 원문 링크는 `mbn.mk.co.kr` 서브도메인이라 이 규칙에 잘못 걸려 "매일경제"로 오분류되고 있었다 — `app/naver_api.py` `OUTLET_DOMAINS`에 `mbn.mk.co.kr` → `MBN`을 별도 등록해(더 긴 도메인이라 `mk.co.kr` 규칙보다 먼저 매칭됨, `koreajoongangdaily.joins.com`과 동일 패턴) 바로잡았다. `mbn.co.kr`(도메인 자체)로 오는 기사도 여전히 `MBN`으로 잡힌다.
- **Publish time display**: `app/naver_api.py` `_search_one_keyword` attaches each article's parsed `pub_date` (ISO 8601, KST) to the result dict purely for sorting/display — PRD's "no publish date in output" rule is about the copy/export line format, not on-screen UI, so this doesn't violate it. `app/renderer.py` `render_article` shows both a fixed `"HH:MM 게시"` (safe to bake into the static HTML since it never changes) and a live "N분 전" computed by the same client-side JS pattern as the real-time view (`renderRelativeTimes`, re-run on every page load/auto-refresh) — both screen-only, never included in `_build_plain_text`. [Updated: 2026-07-24] Windowed per-slot collection: each run only gathers articles published within its configured `start`(exclusive)–`end`(inclusive) window, not the whole day (`_search_one_keyword` `after`/`before` params, computed in `app/scraper.py` `collect_run` via `kst_today_at`). The main article screen (`index.html`) still shows only the latest single run's window, unchanged — only the landing-page word cloud (see below) aggregates across the whole day. Anywhere downstream needs "all currently registered search keywords" as a flat set (sub-heading classification exclusion, the bottom "🤖" keyword block, word-cloud color-coding) uses `app/settings.py` `all_search_keywords` instead.
- **Dedup rule**: keep duplicate articles across outlets/editions, but collapse articles with an *identical* title down to one (keeps the first-seen, so apply after outlet-priority sort). Articles whose title contains a photo-article hint word (`PHOTO_HINT_WORDS` in `app/filters.py`: 포토/사진/화보/포토뉴스/PHOTO, case-insensitive) are excluded entirely, not just deduped — except titles containing `[속보]`, which are always kept regardless of other hint words.
- **Outlet ordering**: broadcasters (KBS, MBC) first, then a fixed list of major outlets (조선일보, 중앙일보, 동아일보, 한국경제, 매일경제, 서울경제, 한국일보, 머니투데이, 이데일리, 연합뉴스, 뉴시스, …), then everything else appended at the end (never dropped) — **unless** the user has picked an outlet whitelist in settings, in which case only the checked outlets are kept, in the user-chosen order (`app/settings.py` `save_outlet_selection`, `app/filters.py` `filter_by_outlet_whitelist`).
- **Output line format** (no publish date shown), customizable via a `{outlet}`/`{title}` template in settings (default shown below); the URL line and the absence of a publish date are not customizable:
  ```
  ㅇ (언론사) 기사제목
  URL
  ```
- **No full-text crawling** — only store the Naver API's `description` summary field. Highlight keyword matches within it in `#C6FF00` (highlight keywords are a separate settings field from search keywords, max 3).
- Empty result for a run → show "💤" (changed from "하나도 없어요" on 2026-07-24), not an empty list.
- Failed scrape → retry up to 3x, 5 minutes apart.
- Header on screen/export: "언론 모니터링 [HH:MM] 기준" using the run's scheduled slot time.
- **Sub-heading classification**: regenerated fresh each run from article descriptions (not fixed categories), max 5 sub-headings, each article assigned to exactly one — except a user's manual drag-across-boundary reassignment (see curation below), which overrides auto-classification as long as that sub-heading still exists in later runs. Every group — including the first — is rendered with a `<소제목N>` label, which can be renamed by the user (renaming only changes the display label, not the underlying grouping key).
- Within a sub-heading, articles are still ordered by the outlet-priority rule above.
- **Curation** (main screen, latest run only): each article has 🗑️ hide/restore (hidden articles stay in storage, just excluded from screen/export/wordcloud; reversible from the settings screen's "숨긴 기사 관리") and ↑/↓ reorder (moves within a sub-heading; at a group boundary, moves the article into the adjacent sub-heading).
- **History**: the last 7 days of runs are browsable (`history.html`), grouped by date → time slot; it does not re-run sub-heading classification, so no per-run curation there.
- **Telegram send** [Added: 2026-08-03]: two independent send paths, both via `app/telegram_bot.py` `send_text()` (splits on `\n` into ≤4096-char chunks for Telegram's per-message limit; never raises, returns `False` on missing config or request failure — a scheduled run or draft view must never break because Telegram is down). (1) Scheduled auto-send: `/telegram` settings screen (`app/settings.py` `save_telegram_settings`, field `telegram_auto_send`, default off) — when on, `main.py`'s `_scrape_and_render` calls `app.renderer.build_latest_plain_text()` (same text the completed screen's copy/export button would produce) and sends it, but only in the same branch where the screen itself is actually regenerated (skips the "0 articles and today already has a run" branch, since that branch intentionally keeps the previous run's screen unchanged — sending would just re-send stale content). (2) Manual send: the "📤 Telegram 전송" button (renamed from "📤 텔레로 보내기" [Renamed: 2026-08-03]) — present on both `preview.html` (`app/preview_renderer.py` `_actions_html`, posts to `/telegram-send-draft`) and `index.html` (`app/renderer.py`, posts to `/telegram-send-scrap`) — sends the page's already-rendered `PLAIN_TEXT` JS variable as-is rather than having the server recompute state, guaranteeing what gets sent always matches what's currently on screen, including any reordering/hiding done moments before.
- **Action toolbar redesign** [Updated: 2026-08-03]: the flat solid-blue `button, a.btn` look was too uniform across unrelated actions, so `index.html`/`preview.html`'s top action row (복사/txt로 저장/Telegram 전송/지난 기사) now uses a softer tonal fill (`.actions button, .actions a.btn` — bg `#EFF6FF`, text `{accent}`, hover `#DCEAFE`) that's more specific than the base rule and so overrides it only inside `.actions`, leaving 🗑️/↑/↓/dropdowns elsewhere untouched. "+ 새 소제목 만들기" is the one exception within that row — being a create action rather than an export/send action, it keeps a distinct ghost-outline style (`.actions .create-group-btn` — transparent bg, `#C7D9F7` border, hover `#EFF6FF`/`#A9C6F5`). Button labels were also clarified: "내보내기" → "txt로 저장", "📤 텔레로 보내기" → "📤 Telegram 전송". The `index.html` action row's "새로고침" link was removed as redundant (the page already auto-refreshes every 60s, see below) — `preview.html`'s separate `.refresh-btn` "🔄 새로고침" (outside `.actions`) stays, since that screen has no auto-refresh.
- Main screen (`index.html`) auto-refreshes every 60s via `<meta http-equiv="refresh">` (no JS needed for this).
- Bottom-of-page summary block (once per run, across all results, in this order): `🤖 AI가 추출한 주요 키워드` (comma-separated list, no `#` tags) then `💬 AI가 읽은 소제목별 주요 요약` (per sub-heading, ≤3 sentences / ≤150 chars).
- Export: copy-to-clipboard or `.txt` download of the sub-heading-grouped list (curation buttons and icon glyphs are excluded from the copied/exported text).
- **Landing page word cloud** (`home.html`, `app/landing_renderer.py`): [Updated: 2026-07-24] aggregates keywords across *all* of today's saved runs (url-deduped), not just the latest run — separate pipeline from article scraping, reads already-stored data only. Regenerated on every request (`app/settings_server.py` `/home.html` route calls `generate_landing_page()` before serving, not just at scrape time). Shows a "* 당일 0시 이후 현재까지의 누적 기준" caption (normal weight, small). [Updated: 2026-07-25] Flat flex-wrap tag cloud (no more fixed radial layout). Search keywords (e.g. a registered person's name) are included in the frequency count here — unlike subheading classification / the article-list "🤖" keyword block, which still exclude them — and rendered in a distinct muted-gray color so they read as "shows up because it's a search term" rather than genuine trending words.
- Data retention: delete stored articles after 7 days.
- Explicitly out of scope for this version: other news sources (Daum, Google News), user accounts/login, email notifications, per-outlet filter/search UI, remote/mobile access off the local network.

## Working rules

- 모든 설명과 주석은 한국어로 작성한다.
- 새 파일은 이 프로젝트 루트 폴더(`my_app`) 안에만 만든다.
- 코드를 바꾸면 반드시 무엇을 왜 바꿨는지 한 줄로 알려준다.
- `.env` 등 비밀 정보 파일은 `.gitignore`에 등록해 두고, 절대 커밋하지 않는다.
- 파일을 지워야 할 때는 바로 삭제하지 말고, `trash-can` 폴더를 만들어 그 안으로 옮겨만 둔다. 작업이 끝난 뒤 사용자가 직접 확인하고 삭제한다.
- 이미 설치된 서브에이전트(bkit의 gap-detector 등)를 필요할 때마다 적극 활용한다.

## 작업 절차(검증 루프)

아래 순서를 매번 반복한다:

1. 변경한다.
2. 결과를 직접 확인한다 (브라우저로 열기/실행).
3. 스스로 코드 리뷰한다.
4. 문제가 있으면 고치고 다시 1)로 돌아간다.
5. 통과하면 무엇을 왜 바꿨는지 한 줄로 요약한다.
