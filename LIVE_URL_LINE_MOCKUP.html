실시간현황 기사 행 — URL 줄을 어떻게 할까

실시간현황 화면에서 그대로 뽑은 기사 8건(2026-09-16 13:47) · 실서비스와 같은 800px 폭·같은 CSS 값
수치는 같은 날 14:05 화면 766건 전수를 브라우저에서 직접 잰 값이다(추정 아님).

지금 무엇이 문제인가

  • 한 행이 세 줄이다 — 메타(언론사·그룹·시각·검색어) / 제목 / URL 통째.
  • URL 줄 폭 실측: 중앙값 308px, 최대 478px. 한 줄을 통째로 쓰는데, 담는 정보는 행 맨 앞 언론사 이름이 이미 말해 준다.
  • 기본 행 82px, 766건이 쌓인 지금 문서 높이가 65,074px. 상단 고정 영역이 433px이라 첫 화면(900px)에 보이는 기사가 5.7건뿐이다.

⚠ 반드시 지켜야 하는 두 가지 (2026-08-13 사용자 결정, HISTORY.md)

  • 원문 보기는 접근이 빨라야 한다 → 메뉴(⋯) 뒤로 숨기지 않는다. 항상 보이는 링크 한 번 클릭.
  • 제목 클릭은 요약 펼치기다 → 제목 자체를 원문 링크로 바꿀 수 없다.

아래 B·C안은 둘 다 이 조건을 지킨다. 제목을 링크로 바꾸는 안은 두 번째 조건에 걸려 애초에 뺐다.

✓ 다른 화면은 이미 이렇게 바꿨다 — 실시간만 남았다

  • 정기 확정본·초안 (2026-08-14) — “밑줄 텍스트 URL이 화면을 산만하게 만들고 줄바꿈·잘림이 잦다”는 지적으로 URL 줄을 없애고 게시시각 옆 원문보기 링크로 옮겼다.
  • 수시 (2026-08-19) — 같은 변경. 당시 목업 실측 한 건당 21.2px 절약, A안 채택.
  • 그때 함께 정한 조건이 “URL이 화면에 없으면 복사가 클립보드로 가는 유일한 길이니 상시 노출한다”였는데, 실시간은 2026-09-01에 이미 복사를 상시 노출로 바꿔 놨다. 전제가 이미 갖춰져 있다.

  • 복사·발송 텍스트는 한 글자도 안 바뀐다. URL은 지금도 화면 표시일 뿐이고, 복사 본문은 data-copy-text가 따로 들고 있다(CODING_CONVENTIONS.md §4).
  • 잃는 것 하나 — URL을 눈으로 확인하던 길. 다만 언론사 이름이 이미 행 맨 앞에 있고, 세 화면이 이미 이 방식으로 돌고 있다.
  • 고칠 자리는 app/live_renderer.py _render_row(.live-url 줄 → .origin-link-text)와 .kw-inline·메타 줄 CSS 두 군데뿐이다.
